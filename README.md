This is a Real estate application developed for a dummy company named BT Real Estate. I used Django to develop this application.

## Running locally

```bash
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
```

By default the app uses a local PostgreSQL database named `btredb`. Set `DB_ENGINE=sqlite` to use SQLite instead (handy for a quick try or for running the tests with `python manage.py test`).

## Configuration

Settings are read from environment variables:

| Variable | Default | Purpose |
|---|---|---|
| `SECRET_KEY` | development-only key | Django secret key. Set a long random value in production. |
| `DEBUG` | `True` | Set to `False` in production. |
| `ALLOWED_HOSTS` | `localhost,127.0.0.1` | Comma-separated host names the site is served on. |
| `DATABASE_URL` | not set | Full Postgres connection string (used in production, e.g. Neon). Takes priority over the `DB_*` variables. |
| `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT` | `btredb`, `postgres`, empty, `localhost`, `5432` | PostgreSQL connection. |
| `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD` | empty | Gmail address and [app password](https://myaccount.google.com/apppasswords) used to email inquiries to realtors. Without them, emails are printed to the console. |

## Deploying (Render + Neon)

The site runs on a free [Render](https://render.com) web service with a free [Neon](https://neon.tech) Postgres database.

1. **Neon:** create a project, then copy its connection string from the dashboard (**Connect**). It looks like `postgresql://user:password@ep-xxx.region.aws.neon.tech/neondb?sslmode=require`.
2. **Render:** **New > Blueprint**, pick this repository, and paste the Neon connection string when asked for `DATABASE_URL`.

On every start the service runs migrations, loads the demo listings into an empty database (`python manage.py seed_demo`) and creates the `admin` user. The admin password is generated by Render: see `DJANGO_SUPERUSER_PASSWORD` under the service's **Environment** tab.
